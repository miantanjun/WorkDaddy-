# WorkBuddy 助手

WorkBuddy 桌面端的**多账号 · 会话同步 · 主题增强**工具集。基于 Chrome DevTools Protocol (CDP) 注入，**零侵入、不修改官方安装包**。

> **本项目是 [babygoton/WorkDaddy](https://github.com/babygoton/WorkDaddy) 的个人维护分支。**
> 原项目作者：babygoton 与 WorkDaddy Contributors。原始代码以 **AGPL-3.0-or-later** 授权（见 [`LICENSE`](LICENSE)）。
> 本分支在原版基础上修复了若干缺陷并追加了部分功能，仅供维护者个人在自有设备上使用。

## 项目简介

WorkBuddy 桌面客户端在本地保存登录信息，同一台电脑同时只登录一个账号。本项目通过 CDP 连接正在运行的 WorkBuddy（Electron）实例：

- 监听登录/认证网络事件与页面加载事件，把登录信息按 `account.uid` 备份到稳定目录；
- 提供本地面板，一键切换登录账号；
- 在新账号下按空间/会话维度同步会话与产物，并按需回切；
- 在同一通道上叠加主题、用量统计、自动化等增强能力。

全程不改动 WorkBuddy 的安装文件，卸载本工具不影响客户端本身。

**运行环境**：Windows 10 及以上，x64。

**前置条件**：本机需已安装 **WorkBuddy** 桌面客户端。本工具是它的增强插件，**不含 WorkBuddy 本体**。

## 功能特性

安装后面板以多个标签页组织功能：

| 标签页 | 主要能力 |
|---|---|
| **账号** | 账号列表与一键切换、当前账号高亮、切换后自动同步会话、闲置超时自动切回主账号、登录方式说明与优缺点悬停提示 |
| **主题** | 主题与壁纸切换、登录/弹窗等界面文案与配色增强 |
| **会话** | 会话按空间分组浏览、搜索与筛选、单个/批量迁移与删除、会话自动复制规则、复制进度条、云端残留清理 |
| **空间** | 只读的空间占用扫描：按账号/按空间统计磁盘占用与文件数，硬链接去重、可中断、支持点列头排序 |
| **模型** | 模型列表、备份与切换 |
| **增强** | 附加的界面与交互增强项 |
| **自动化** | 自动化任务管理，含**定时发送**（到点自动向指定账号/对话发送预置命令）与内置的「限流自动切号续跑」 |
| **电脑** | 本机进程与运行状态、日志查看、重启等维护操作 |
| **关于** | 本工具与 WorkBuddy 的版本信息、检查更新 |

## 与上游的差异

本分支基于上游 **WorkDaddy 1.2.3** 持续维护，当前版本 **1.4.3**。相较上游的改动如下。

### 缺陷修复

| 内容 |
|---|
| 「假退出」流程中断（`taskkill` 优雅失败被当成致命错误），导致登录文件未删、应用未重启 |
| 删除账号备份后重新登录，会因幂等登记丢失而**重复复制**已有会话 |
| **切号复制产生重复副本**：血缘登记体检会把「同一账号出现两个成员」拆成新血缘并改写会话索引，导致下次切号把已有副本当成新会话再复制一份（一次可能多出几十份重复会话）。现改为**只体检不拆分**，并在复制前按 `created_at` 指纹认领目标账号里已有的同源副本（必要时**合并血缘**），另新增 `POST /api/sessions/purge-copy` 用于「只删这一份副本、不级联」的重复清理 |
| `daemon` 在原生启动器模式下权限检测失败导致崩溃重启循环（加了 PowerShell 回落） |
| 归档态被对账冲掉；原生软删未向下级联；软删探测误伤「已被同 lineage 级联删掉」的正常竞态 |
| 切号后 `session.open` 打不开会话——加载中的点击被去重逻辑吞掉、兜底预算过短（15s），以及**会话侧栏处于收起状态时列表根本未挂载**（原逻辑会空滚到 40 000px 后早退）。现改为先唤醒侧栏再找行，并对「列表未挂载」与「列表已挂载但没这一行」分流处理 |
| **定时发送的发送步骤被静默吞掉**：按钮的 `disabled` 属性与真实闸门（React 侧 `semanticDisabled`）不一致，点击后没有任何反馈。现改为直接调用 composer store 的发送接口，与按钮走同一条发送链路但绕开那层 DOM 看不见的闸门 |
| 发送前输入框已有内容时一律拒绝发送，导致上一次失败遗留的草稿把后续任务全部挡掉。现按内容指纹（忽略空白）认出「自己上次留下的残留」并清掉重打 |
| 「目标会话正在运行」误判：会话 hydration（历史加载）被当成任务在执行，刚打开的会话无法立即发送 |
| 账号**用量归属**错记：切号复制产生的副本被记到源账号；已删会话的用量整条丢失。现按物理文件判定归属，并覆盖全部会话 |
| 空间扫描派生的复制排队清单排序口径不一致，导致复制队列顺序不稳定 |
| 更新器「检查更新」可能卡死（新增硬超时）；`parseSha256` 调用漏改 |
| 内置工具 `rescan-and-report` 读错进度字段，白轮询到超时 |
| CI 缺陷：Windows runner 上 Python 的 stdout 为 cp1252，中文输出直接中断构建步骤；`.cmd` 换行校验依赖 Git Bash 的 `grep` 产生误报；已存在的 Release 更新时正文 SHA256 落后一版 |
| 安装器 `CreateCustomForm` 空参调用导致 Inno Setup 编译失败 |

### 功能新增

| 内容 |
|---|
| **限流自动切号 + 同一模型续跑**：检测到限流横幅后自动切到其它账号继续任务。切号后**先等会话同步完成（默认 120 秒、至少 60 秒，可配），再在原会话的副本里继续**（上下文不丢）；副本未就绪才降级为新建任务重发。续跑只发「继续」而不重发全文，并在发送前先验证同步完整。续跑结束后自动切回主账号，并在**桌面生成大白话日志**（`WorkDaddy-账号切换日志-<日期>.txt`） |
| **非主账号闲置超时自动切回主账号**：面板「账号」页可折叠卡片里配置（默认 30 分钟，5~1440 可调），切回时同样同步会话并写桌面日志 |
| **切号后自动同步会话**：手动切号、限流切号、闲置切回三条路径共用同一实现，切号即触发 |
| **「立即同步」**：不切号把会话推到指定账号；**目标账号默认当前账号，源账号可留空**（留空 = 除目标外的所有账号），并支持暂停/继续同步 |
| **单向级联删除**：删主账号的会话向下级联，删非主账号的只删本账号那份 |
| **空间占用扫描**（只读）：按账号 / 按空间统计磁盘与文件数，硬链接去重，可中断 |
| **云端残留检测与清理**：桌面删除只删本机，而手机端/其它电脑读的是**云端那份**（删除不会通知云端），于是「桌面删干净了、手机端还在」。会话页新增可折叠的「云端残留」卡片：列出「本机已删、云端仍在」的会话，按账号分组清理；跨账号的残留必须切到该账号才能清（云侧按当前登录账号鉴权），按钮走两段式确认、清完自动切回。**删除会话时也会顺带清一次云端**，从源头不再产生残留 |
| **定时发送**：到点自动向指定账号 / 指定对话发送预置命令；配套**核验台账**，把「到点没发出去」的任务在桌面日志里列出来 |
| **归档改为「仅主账号」概念**：归档会话不再跟随跨账号复制，也不再出现在非主账号视图里 |
| **成长任务一键完成**（v1.4.2）：面板浮层列出每日成长任务，一键按档位自动跑完并领奖；**档位是安全闸门**（最高档默认关闭，须显式打开） |
| **会话体积可视化**（v1.4.3）：会话列表每行显示体积，新增**体积筛选**（10 MB / 100 MB / 1 GB 档），汇总条显示**账号总量**（不受筛选影响） |
| **自动化协议 V3**（v1.4.3）：`account.forEach` 支持 **`prepare`**（切换前只读准备）与 **`condition`**（不满足就**不切号也不执行**）；`switch: true` 改为**等本次会话同步成功**之后才继续执行 steps，并暴露 `sync` / `stopRequested` 运行状态 |
| **签到不插队**（v1.4.3）：多账号批量签到时，**当前账号**的请求不会被其它账号的签到挤掉 |
| 界面辅助：**当前账号高亮**、空间页把「时间戳目录」翻译成「任务对话」、登录方式弹窗补「优缺点」悬停提示、关于页**双版本展示**与「检查更新」按钮 |

### 功能改进

| 内容 |
|---|
| 会话自动复制拆成两阶段（正文先落盘、产物后搬），并按体积**升序**排队，避免巨型会话堵塞整条队列 |
| 会话页常驻**复制进度条**：当前会话标题、`已复制/总数` 计数、文件级进度、已省空间 |
| 产物目录改用**硬链接**去重（冻结文件三分支增量链接，失败回落复制），省下数百 MB 磁盘 |
| 空间扫描派生复制排队清单，排序同时纳入**产物体积档**与**产物文件数档** |
| 删除确认框补一句「本机删除不会同步到其它设备，手机端／其它电脑上仍可能看到这些会话」 |
| **会话同步改造**（v1.4.3）：**取消 64 MiB / 20000 文件两道上限**（原先超限直接不同步），配套**惰性字节加载**（内存占用从「全部会话」降到「本次实际要复制的量」，只删上限不加惰性读会让内存无界增长）；新增**文件级指纹缓存**（落盘在数据目录，默认 `mtime` 路径完全不受影响）；同一账号**大文件不再反复重读**，**单个会话超过 100 MB 时给出「同步可能较慢」的建议性提示**（只提示，**不裁剪任何文件**） |
| 会话自动复制新增**作业级数据量与速率**：进度条显示**平均复制速率**与**已复制 / 总量**（速率只算搬运阶段，不含排队与切号等待） |
| 更新器补齐限流 / 断网兜底，并新增可独立运行的护栏自检 `tools/updater-guard.js` |

## 安装

### Windows

1. 打开本仓库的 [Releases](../../releases) 页面，下载与你的客户端匹配的最新安装包：
   - `WorkDaddy-Setup-<版本>.exe` —— 对应 **WorkBuddy**（`workbuddy-cn`）
   - `WorkDaddy-AI-Setup-<版本>.exe` —— 对应 **WorkBuddy AI**（`workbuddy-ai`）
2. 直接双击安装（**无需管理员权限**，也**不要**选「以管理员身份运行」）
3. 安装程序会自动识别本机的 WorkBuddy 客户端；如未识别到，手动选择 `WorkBuddy.exe`
4. 装完双击桌面快捷方式即可

安装位置默认为 `%LOCALAPPDATA%\Programs\WorkBuddy 助手`。

### 更新

打开面板 → **关于** → 点「立即更新」。程序会自动下载新版本并安装。

> ⚠️ 更新过程会**先关闭 WorkBuddy**（安装器要求客户端完全退出），装完后自动重新拉起。请先保存好正在进行的工作。

## 使用方法

1. 本工具安装后以**独立进程**运行，通过 CDP 连接已启动的 WorkBuddy 窗口；若客户端未以调试端口启动，守护进程会自动降级为文件监听模式，基础的备份 / 切换功能不受影响。
2. 点击桌面快捷方式打开面板（WorkBuddy 窗口右下角也有常驻入口），在「账号」页管理账号：登录过的账号会自动备份，此后可一键切换。
3. 在「会话」页按空间浏览会话，配置「随空间自动复制」或「切换账号时自动复制」，设好后切号即自动搬运会话与产物。
4. 在「自动化」页管理定时任务；限流自动切号续跑已作为内置任务随包分发，可在该页查看与启停。
5. 每次定时任务的执行结果、切号记录都会写进**桌面上的大白话日志**，便于事后核对到底发出去没有。

日志与数据目录见下一节。

## 配置说明

### 数据目录

`%APPDATA%\WorkDaddy` —— 存放账号备份（`accounts/`）、运行日志（`daemon.log`）、自动复制规则、自动化任务与调度台账等。

### 环境变量

| 变量 | 说明 |
|---|---|
| `WBSWITCH_AUTH_FILE` | 登录信息文件路径（默认 CodeBuddyExtension 下 `auth/workbuddy-desktop.info`） |
| `WBSWITCH_DATA_DIR` | 备份数据目录（默认 `%APPDATA%\WorkDaddy`） |
| `WBSWITCH_PORT` | 本地面板端口（显式指定时固定；未指定时从 47832 起尝试） |
| `WBSWITCH_CDP_PORT` | WorkBuddy CDP 首选端口（被占用时自动切换到 9222-9232 / 9333） |
| `WBSWITCH_WORKBUDDY_BIN` | VPC / 便携版目标程序路径 |
| `WBSWITCH_UPDATE_REPO` | 自动更新所指向的仓库（默认 `miantanjun/WorkDaddy-`） |
| `WBSWITCH_UPSTREAM_REPO` | 上游仓库标识（默认 `babygoton/WorkDaddy`） |

本地 HTTP API 需要携带当前 profile 的令牌（落盘于数据目录的 `.api-token`），健康检查可用 `GET /api/status` 读取版本与 CDP 连接状态。

## 构建

### GitHub Actions（推荐）

推一个 `v*` 标签，或在 Actions 页面手动触发 `Build & Verify Windows Setup`（可留空版本号，自动从 `scripts/daemon.js` 的 `DAEMON_VERSION` 读取）：

```
Go 1.27 编译 Windows 原生启动器
   ↓
scripts/build-win-zip.sh        打暂存包（含 Node 运行时、内置壁纸）
   ↓
Inno Setup 6.7.1                生成 WorkDaddy-Setup-<版本>.exe
                                与 WorkDaddy-AI-Setup-<版本>.exe
   ↓
scripts/verify-win.cmd          自检（关键文件 / JS 语法 / PS1 语法）
   ↓
发布到 GitHub Release
```

构建前会强制校验两件事：受跟踪的 `.cmd` 文件必须是纯 CRLF；`scripts/builtin/` 下的内置资产（`nebula/theme.json` 与 `wallpapers/`）必须存在。Release 正文会带上两个安装包的 SHA-256，作为客户端校验兜底。

产物同时作为 Actions artifact 保留。

### 本地构建

需要本机具备 **Go 1.27**、**Inno Setup 6.7.1** 与 Node.js 运行时，然后依次执行 `scripts/build-win-zip.sh` 与 `scripts/build-win-installer.ps1`（按 profile 传 `-Profile workbuddy-cn` / `workbuddy-ai`）。

## 目录说明

| 路径 | 说明 |
|---|---|
| `scripts/daemon.js` | 后台守护进程：本地 HTTP API、账号切换、会话复制、自动更新、定时任务调度 |
| `scripts/inject.js` | 注入 WorkBuddy 页面的前端组件（面板、进度条、主题） |
| `scripts/lib.js` | 共享库：账号元数据、自动复制规则、会话索引 |
| `scripts/win-launcher.js` | Windows 启动器逻辑（进程检测、权限边界、daemon 生命周期） |
| `scripts/watchdog.js` | 守护进程看门狗：daemon 退出后自动用磁盘上的新代码重启 |
| `scripts/space-scan.js` | 空间占用扫描（只读、可中断、硬链接去重） |
| `scripts/session-transfer.js` / `scripts/sync.js` | 会话迁移与「立即同步」实现 |
| `scripts/limit-failover.js` / `scripts/idle-switchback.js` | 限流自动切号续跑、闲置自动切回主账号 |
| `scripts/scheduled-send.js` / `scripts/schedule-ledger.js` | 定时发送与执行核验台账 |
| `scripts/token-stats.js` / `scripts/credit-*.js` | 账号用量归属与额度统计 |
| `scripts/win/workdaddy.iss` | Inno Setup 安装器定义 |
| `scripts/windows-native/` | Windows 原生启动器（Go 源码） |
| `tools/updater-guard.js` | 更新器护栏自检（可独立运行） |
| `.github/workflows/` | GitHub Actions 构建流程 |

数据目录：`%APPDATA%\WorkDaddy`（账号备份、日志、自动复制规则、自动化任务）。
